## Applying (built this session)

- Built: `POST /applications` (async batch, polled via `GET /applications/batches/:id`), `GET /applications`, `POST /applications/:id/opened`, `GET /applications/:id/cv`; CV tailoring per job; `integrations/email` (Resend over fetch + a fake that writes to `tmp/outbox/`); `EMAIL_REDIRECT_TO` dev safety net. `POST /cv/pdf` already existed — the renderer got real Helvetica metrics for wrapping, right-aligned dates, section rules, compact skills; and it now returns 200 (was Nest's default 201, against the contract).
- **Before real companies get emails**: verify a sending domain in Resend (SPF + DKIM, DMARC), set `EMAIL_FROM_ADDRESS` on it, and clear `EMAIL_REDIRECT_TO`. Also review legally/ToS whether emailing listings found via an aggregator on the user's behalf is acceptable per source.
- Tailoring only reorders/rewords bullets and reorders skills; a reworded bullet is rejected (entry falls back to the original) if it contains any number, acronym, tool-like token or mid-sentence proper noun not already in that same entry. This can be over-strict (a legit synonym that happens to be capitalized gets rejected) — fine, the fallback is the user's own wording. No summary is generated; `Cv.summary` is still never written anywhere.
- The email path requires `contact.email` on the CV (it's the Reply-To); without it the application fails with a clear Arabic message and can be retried after the user adds one.
- Processing is in-process (like uploads): a pool of 2 per batch. Interrupted `processing` rows (restart/crash) are picked up by a 60s sweep after 3 minutes; a resumed email reuses its idempotency key (`<applicationId>-<batchId>`) so Resend won't double-send within its 24h window. Multiple API instances would need a real queue or row locking.
- No bounce/complaint handling yet — Resend webhooks (`email.bounced`, `email.complained`) should flip an application to a "bounced" state; the contract has no such status yet.
- Job listings' `applyEmail` comes from scanning the snippet (`resolveApplyMethod`) — worth a sanity check (e.g. ignore no-reply addresses) once real Jooble data flows.
